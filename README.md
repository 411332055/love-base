# 我們的戀愛遊戲基地

兩個人專用的小網站：一起寫日記、傳照片、許願、抽題，資料即時同步。

網址：https://411332055.github.io/love-base/

## 怎麼使用

1. 打開網址，輸入你們約好的暗號，選「寒冰」或「夏夏」。
2. 手機可以加到主畫面當 App 用，步驟在「更多」→「設定」裡。iPhone 要加到主畫面才收得到推播通知。
3. 輸入同一組暗號就會進到同一個基地，看到同一份資料。

暗號是這個基地唯一的門鎖，知道的人就能看和修改全部內容，所以請用別人猜不到的長暗號，也不要外流。忘記暗號就進不去了，網站沒有找回功能，請自己記在安全的地方。

## 選單

手機在底部、電腦在左側，一次只顯示一個區塊。在頁面中間左右滑也可以切換。

| 分類 | 內容 |
|---|---|
| 今天 | 稱號和 XP（含週年紀念日與雙方生日倒數）、提醒（時光膠囊到期、備份、照片空間、你不在時的動態）、討抱抱、今天還差什麼、連續天數 |
| 日記 | 今天的照片（點照片右下角 `✏️` 可寫一句話）和日記（可按表情貼圖與留言回應）；星期日多一個「這週回顧」 |
| 互動 | 抽題（每天輪流抽一題、每月換主題，揭曉前可修改答案、可自訂題目）、願望清單（分類：想吃、想去、想做；可以約定日期，前一天會推播提醒、月曆上看得到；已完成的可以「看那天」） |
| 回憶 | 月曆（含全部日記與搜尋）、照片牆（大圖可雙指或雙擊放大）、回顧（那年／那月／一週前的今天、幸福指數曲線、月度回顧、時光膠囊、回憶扭蛋機）、回憶書（每月與年度總結） |
| 更多 | 成就稱號、規則、設定（推播通知、垃圾桶、備份、照片原圖、照片空間、更換暗號、外觀、震動、區塊順序） |

## 計分

XP 是兩個人共用的一個總分，所有加分都要兩個人一起達成，而且沒有扣分：完成過之後，就算刪掉日記或照片，分數也不會減少。

| 同一天兩個人都完成 | XP |
|---|---|
| 傳照片 | +10 |
| 星期日寫這週回顧 | +10 |
| 連續每滿 7 天（兩人當天都有傳照片或寫日記） | +10 |
| 抽題過關（兩個人都回答完同一題） | +10 |

2026-11-16（含）以前兩個人都寫日記的 +10 XP 會永久保留；從 2026-11-17 起日記改為自由填寫、不加分。許願和完成願望也不加分。

## 抽題

- 寒冰和夏夏**隔天輪流**抽題，一天一題；輪到的人在還沒有人作答前可以「換一題」。
- 題目來自 `questions.json`，每個月一組主題，目前寫到 2028 年 10 月。某個月沒有題庫時，會改用 `app.js` 裡的基本題庫 `QUESTIONS`。自訂的題目每個月都會一起抽。
- 新增月份只要在 `questions.json` 加一組 `"年-月": { "theme": "主題", "q": ["題目", ...] }`，不用改程式。

## 資料備份

到「更多」→「設定」→「資料備份」：

- **完整備份**：下載一個 HTML 檔，用瀏覽器打開就能讀，也能用同一個檔案把資料補回網站。補回時只新增目前沒有的資料，不會改動現有內容。
- **下載這個月的照片**：選月份，得到一個壓縮檔，裡面是一張張的照片，可以直接存到 Google 相簿或雲端。有設定「照片原圖」的照片會是原圖。

## 照片原圖

網站上的照片會壓小（最長邊 1280 像素），畫面才跑得快。「設定」→「📷 照片原圖」設定好之後，新照片的原圖會在背景另外存到寒冰的 Google 雲端硬碟「戀愛基地原圖」資料夾（Apps Script 專案「戀愛基地 原圖」），下載、長按存照片、打包一個月的照片時拿到的就是原圖。原圖還沒傳完就關掉 App，下次打開會接著傳；雲端連不上時下載會改用壓小的版本。設定之前傳的照片沒有原圖。

## 震動沒有感覺

到「更多」→「設定」按「📳 測試震動」，看按鈕旁邊的字：

- 寫「已經叫手機震了」卻沒震：手機在**靜音模式**，或系統的觸控震動被關掉。Samsung 要切到「震動」或「音效」模式。
- 寫「這個瀏覽器不支援震動」：可能是在 LINE、IG 裡打開的，請改用 Chrome。
- iPhone 需要 iOS 18 以上，而且強度固定。

## 定期維護

| 多久一次 | 要做的事 | 怎麼做 |
|---|---|---|
| 每個月 | 下載含原圖的完整備份，存到 Google 雲端硬碟 | 見上面「資料備份」。網站超過 30 天沒備份會在首頁提醒 |
| 每次改網站後 | 確認 GitHub 自動檢查是綠色勾勾 | 打開 GitHub 的 love-base，看最新那筆提交旁邊的符號；紅色叉叉就是有東西壞了 |
| 每半年 | 看照片空間用了多少 | 「設定」→「🗜️ 照片空間」→「檢查照片空間」。2026 年 11 月約一天 2.6 張照片，估計 2029 年才會用滿 1 GB |
| 超過 700 MB 時（每月 1 號晚上會自動推播提醒） | 決定要不要擴充空間 | 升級 Firebase 付費方案（網站不用改），或把照片搬到 Cloudflare R2（要改程式）。先確認備份過再動 |
| 改了推播小郵差的程式碼時 | 重新部署 Google Apps Script | Apps Script 專案「戀愛基地 通知」貼上新程式碼 →「部署」→「管理部署作業」→ 鉛筆圖示 → 版本選「新版本」→「部署」。網址不會變 |
| 2028 年 9 月前 | 補 2028 年 11 月以後的抽題題庫 | 在 `questions.json` 加月份；自動檢查會在剩不到兩個月時提醒 |
| 收不到紀念日提醒時 | 確認自動提醒沒被 GitHub 暫停 | 提醒每次執行都會自己重新啟用，正常不會停。萬一停了：GitHub 的 Actions 頁籤 →「紀念日前一天提醒」→「Enable workflow」 |
| 有空時 | 確認 Google 和 GitHub 帳號開了兩步驟驗證 | 網站、資料庫和推播郵差都掛在這兩個帳號下 |

## 技術資訊

- **網站**：放在 GitHub Pages，由 `main` 分支的根目錄發布，推送到 `main` 後約一兩分鐘更新。
- **資料**：存在 Firebase Firestore（專案 `love-base-eec24`，免費方案），路徑是 `rooms/{暗號}/{集合}/{文件}`。
- **集合**：`diary` 是日記，`photos` 是縮圖和說明，`pics` 是原圖，其他資料都放在 `done`（文件 id 是 `x~種類~id`），這樣就不用另外改規則。
- **規則**：修改 `firestore.rules` 後，要到 Firebase 主控台的 Firestore「規則」頁貼上並發布才會生效。
- `index.html` 裡的 Firebase apiKey 公開是正常的，真正保護資料的是規則和暗號。
